# 字幕コラボ v29 — 案件別ルーム

練習用は常設・認証不要。案件ルームは案件名とパスワードで作成します。管理者アカウントは不要です。認証済みの参加者は、その案件のパスワード変更・削除ができます。案件名はルーム一覧に公開されます。

各ルームの担当A/B/C、入力、編集受信、字幕表示、送信待機、投影済みログ、文字数・色・表示設定、スルーモードは独立しています。校閲は各ルーム1人です。従来のURLは新しいUIではルーム選択画面に移動します。v28の接続は公開練習用だけに接続します。

## 起動・確認

- Node.js 20以上、`npm ci`、`npm start`。
- `npm test` は既存通信動作、複数ルーム・認証・分離・再接続・保存のテストを実行します。
- ローカルで隣の `subtitle-ui` フォルダを配信する場合は `LOCAL_TEST_FRONTEND=1 npm start` → `http://localhost:3001/test/`。
- UIは既存のVercel、サーバーは既存のRenderを使用します。新しい外部サービスは不要です。

## 保存範囲

ルーム名・パスワードのソルトとハッシュを `ROOM_STORE_PATH`（省略時 `.data/rooms.json`）に保存します。パスワードの平文は保存しません。入室トークンはブラウザに保存し、7日間の通信再接続に使用します。サーバー再起動・パスワード変更時は再認証が必要です。

**Renderで永続ディスクが設定されていない場合、デプロイや環境の再作成でルーム定義は消える可能性があります。** 継続保存する場合は既存の永続ディスク内のファイルを `ROOM_STORE_PATH` に指定します。この更新は有料ディスクの追加やRenderの契約変更を行いません。

原稿・字幕・待機・ログ・共有設定はv28と同じくメモリ上であり、サーバー再起動でリセットされます。校閲の下書きはルーム別のsessionStorage、前回文字数はルーム別のlocalStorageに保存します。別案件へ下書きや文字数を移しません。

パスワード変更で対象ルームの接続を切断し、古いトークンを無効にします。ルーム削除で対象の原稿・ログ・字幕・待機を破棄します。練習用は削除・パスワード変更できません。

## 公開更新

サーバーとUIの両mainを更新します。運用画面は更新完了後に開き直してください。作業中のサーバー更新では従来どおりメモリ上の字幕・原稿がリセットされます。
